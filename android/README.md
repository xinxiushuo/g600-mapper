# G600 手柄映射（Android）

把手柄按键映射成屏幕上的触摸点。悬浮键位可以用手指拖到任意位置，锁定后触摸穿透，不挡游戏操作。

## 怎么拿到 APK

### 方式 A：直接下载（推荐，免登录）

```
https://github.com/xinxiushuo/g600-mapper/releases/latest/download/app-debug.apk
```

手机浏览器直接打开这个链接就能下，不用登录 GitHub。
下载后允许「安装未知来源应用」即可安装。

> 仓库：https://github.com/xinxiushuo/g600-mapper
> 每次 push 到 `main` 都会自动重新打包，并覆盖更新到上面这个 `latest` 直链。

### 方式 B：GitHub Actions 里手动下载

仓库顶部 **Actions** 标签 → 点最新一次 `Build APK` → 页面底部 **Artifacts** → 下载 `G600Mapper-debug-apk`（zip，解开是 `app-debug.apk`）。
注意：Artifacts 必须**登录 GitHub** 才能下载，所以推荐用方式 A。

### 方式 C：Android Studio（想改代码就走这个）

1. 装 [Android Studio](https://developer.android.com/studio)（约 3 GB，含 SDK）
2. `File → Open` 选择这个 `android` 目录
3. 等 Gradle 同步完，点绿色 ▶ 运行，或 `Build → Build Bundle(s)/APK(s) → Build APK(s)`
4. APK 在 `app/build/outputs/apk/debug/`

命令行打包（需已配好 JDK17 + `ANDROID_HOME`）：`bash build.sh`

## 用起来（v1.2）

1. 打开 APP → 点 **② 开启无障碍服务** → 在系统列表里找到「G600 手柄映射」并打开
   - 服务开启后**不会自动显示任何浮窗**，手机和平时一样
2. 点 **手柄输入测试** → 按手柄上的键，记下每个键显示的 `keyCode` 数字
   - 如果这里什么都读不到，说明 Android 没把手柄识别成 HID 手柄，后面的映射也没意义
3. 回主页 → 点 **③ 显示键位并编辑** → 把每个圆点拖到游戏里对应按钮的位置
   - **单击**某个圆点 → 圆点变成「按键…」→ 按手柄上要绑的那个键 → 绑定完成
   - 圆点上显示的名字和实际按键不符，就用这个办法重新绑一次
4. 点 **④ 锁定并开始映射** → 切到游戏
5. 任何想退出的时候：点屏幕右上角那个**红色小方块**，立刻停止映射并清掉所有浮窗；或者回到 APP 点 **⑤ 停止并清除浮窗**

### 摇杆和方向键（v1.2 新增）

屏幕上有两种圆点：**小圆点**是按键，**大圆环**是摇杆区域。默认布局已经带上了：

| 圆环 | 标字 | 推到哪儿 | 干什么 |
|---|---|---|---|
| 移动摇杆 | 移（青色） | 游戏左下角摇杆底盘，**圆心对准底盘中心** | 推左摇杆 / 按十字键 → 人物朝该方向持续移动 |
| 视角摇杆 | 视（橙色） | 右边屏幕任意空白处 | 推右摇杆 → 视角持续转向（推得越远转得越快） |

- **单击大圆环** = 在「移 / 视」之间切换
- **长按大圆环** = 换大小（10% / 15% / 22% 屏幕短边）。视角转太快就把「视」调小
- **十字键默认当方向盘**：推 ↑↓←→ 就是让「移」摇杆朝那个方向走（和对角）。
  想把它当 4 个独立按钮（比如切枪、开地图），点主界面 **「添加方向键圆点 ↑↓←→」**，
  加完之后十字键只当按钮、不再控制移动 —— 两种用法不会打架

原理和前提：

- 「移」= 在摇杆中心到该方向的固定点上**长按 3 秒**（自动续）。
  这要求游戏里把「移动摇杆」设成 **固定**（和平精英默认就是固定）。
  固定摇杆的判断依据是"手指相对底盘中心的偏移"，所以手指直接按在偏移点就等于把摇杆推到底。
- 「视」= 从中心向该方向**每秒短滑 8 次**。视角是"滑多少转多少"，连续短滑就是匀速转向。
- 摇杆轴数据只有 **Android 14 及以上**才开放给无障碍服务（`onMotionEvent` + `setMotionEventSources`）。
  低于 14 的手机会提示「系统不开放摇杆数据」，此时「移」自动改用十字键驱动，视角摇杆无效。
  主界面状态区会实时显示 `已收到摇杆数据（左 x,y 右 x,y）` 或 `还没收到`。


### 关于覆盖安装

从 v1.1 起，构建使用仓库里固定的签名文件 `keystore/g600.p12`（不是每次自动生成的 debug key），
所以**以后新版本可以直接覆盖安装，不用先卸载**。

唯一的例外：v1.0 是用随机 debug 签名打的包，和现在这个签名不一致，
装 v1.1 之前必须先卸载一次旧版。

### 关于「触屏失效」

v1.0 有一个严重设计错误：悬浮层用了一个**全屏窗口**，为了能拖动就必须让它可触，结果整块屏幕的触摸都被它吃掉，表现为「手机触屏完全失效、APP 也点不开、关不掉」。

v1.1 改成**每个键位一个独立的小窗口**（52dp 圆形），窗口以外的地方永远是空的，触摸天然穿透。所以现在：

- 浮窗只在这 12 个小圆点上占触摸，其它地方完全不挡
- 圆点在锁定模式下整块 `FLAG_NOT_TOUCHABLE`，连圆点本身也不挡
- 右上角红色小方块始终可点，是随时可用的「逃生口」

> 如果你现在装的是 v1.0 并且屏幕已经卡死：**长按电源键重启手机**。重启后服务重连时处于锁定模式（不可触），触摸会恢复正常，然后装 v1.1 覆盖。实在不行进「设置 → 无障碍」把「G600 手柄映射」关掉。


## 单击 / 连发（重要）

每个圆点有两种模式，**默认是单击**：

| 模式 | 边框 | 行为 | 用在哪 |
|---|---|---|---|
| 单击（默认） | 青色 | 按下时点一次，就一次 | 点桌面图标、点技能/菜单按钮 |
| 连发 | 橙色 | 按住时每 120ms 点一次 | 需要"按住不放"（开火、蓄力、持续移动） |

切换方式：**编辑模式下长按圆点 0.5 秒**，会弹提示并改变边框颜色。

> 连发做不到真正的长按。Android 的 `dispatchGesture` 同一时刻只能有一个手势，
> 无法"发一个手势然后一直按住"，只能高频重点近似。所以射击类游戏里手感会偏"连点"。

## 检查注入是否生效

主界面有个 **「测试点击（屏幕中心点一下）」** 按钮。点它：

- 提示 **✓ 已注入点击** → 注入链路正常，问题只在坐标或模式
- 提示 **✗ dispatchGesture 返回 false** → 服务缺少手势权限（`canPerformGestures`），检查无障碍是否真的启用
- 提示 **✗ 手势被系统取消** → 有别的无障碍服务在抢手势

这是排查"按键有高亮、屏幕不动"最快的一步。

## 版本号在哪看

主界面最底部、以及「手柄输入测试」页最底部，都有一行灰色小字：

```
v1.2 (3) · 构建 2026-11-15 12:30
```

- `v1.2 (3)` 是 APK 的 `versionName` / `versionCode`，从 `PackageManager` 实时读取
- `构建 …` 是 CI 真实的编译时间（北京时间），每次出包都会变 —— **判断新旧包看这个**
- **长按这一行**会复制「版本 + 构建时间 + 手机型号 + 安卓版本」到剪贴板，反馈问题时直接粘

实现：`AppInfo.kt` 提供数据（`BUILD_STAMP` 常量会被 CI 用 `sed` 替换成真实时间），
`VersionFooter.kt` 负责渲染，两个页面共用同一份。

## 曾经的 bug：按键有反应但屏幕完全没动作

v1.1 前三版都存在这个致命问题，原因三个叠加：

1. **无障碍配置缺 `android:canPerformGestures="true"`**
   —— 没有这一行，`dispatchGesture()` 静默失败，一次手势都发不出去。只补这一行就已经解决 90%。
2. **手势被自己打断**：旧代码每 40ms 发一次、每次时长 50ms。
   `dispatchGesture` 会用新手势取消还没执行完的旧手势，于是每个手势都在 45ms 处被掐掉，
   系统判定"手势已取消"，不产生点击。现在改成时长 45ms、间隔 120ms。
3. **路径零长度**：旧代码只有 `moveTo`，没有 `lineTo`。部分机型不把零长度路径当有效点击。
   现在补一个 0.5 像素的 `lineTo`（远小于触摸阈值，不会变成滑动）。

另外坐标从 `displayMetrics`（不含系统栏）换成真实全屏尺寸（`currentWindowMetrics`），
否则点击位置会整体偏上，点图标时容易点空。

## 能力边界（重要，先说清楚）

非 root 环境下，这个 APP 靠无障碍服务的 `dispatchGesture` 注入触摸，它有几个硬限制：

| 能力 | 支持情况 |
|---|---|
| 单个按键 → 点击/长按屏幕上某点 | ✅ 可用 |
| 多个按键同时按住（多指） | ✅ 可用（合并成一个多指手势） |
| 摇杆 → 屏幕虚拟摇杆移动 | ✅ Android 14+ 可用（长按近似）；14 以下用十字键代替 |
| 摇杆 → 屏幕视角转向 | ⚠️ Android 14+ 可用（连续短滑近似，转向手感偏"步进"） |
| 边移动边开火 | ⚠️ 会有顿挫：每次点击都会取消摇杆那条长按手势，60ms 内自动补回来 |

为什么摇杆只能用近似：`dispatchGesture` 同一时刻只允许一个手势在执行，新的会取消旧的；
`StrokeDescription` 时长一到手指必定抬起，**没法真正无限期按住**。
所以移动用「3 秒长按 + 到期重按」，视角用「每秒 8 次短滑」。想要 1:1 的真实摇杆，
只有三条路，都不是非 root 能解决的：
- **root** → 写 `/dev/uinput` 虚拟触摸设备（最接近真机）
- **LSPosed / Xposed** 钩子 → 直接改游戏的输入处理
- **游戏原生支持手柄** → 这是最省事的，很多游戏（原神、和平精英、大部分模拟器）本来就不用映射

另外三个已经实测确认的事实（Windows 侧验证，Android 同理）：

| 键 | 实际情况 | 能不能映射 |
|---|---|---|
| **BACK** | 走 Consumer 通道发 `AC Back`，到 Android 上变成 `KEYCODE_BACK` | ✅ 能，但要按设备来源区分，否则会吞掉手机返回键（代码已处理） |
| **HOME** | 发 `AC Home`，Android 会直接回桌面 | ❌ 系统级保留键，无障碍拦不住，建议别用 |
| **感叹号键** | 蓝牙下不发数据；**2.4G 下正常发 `Help 0x0095`** | ⚠️ 要看 Android 有没有把这个 usage 翻译成 keycode，装上用测试页按一下就知道 |

> **重要**：感叹号键请用 **2.4G 模式**。蓝牙固件把它砍了，2.4G 没砍。
> 如果 Android 端读不到它（系统映射表里没有 `0x0095`），那就只剩 root/uinput 或 LSPosed 一条路。

## 代码结构

```
app/src/main/java/com/g600/mapper/
├── MainActivity.kt        权限引导 + 开关 + 摇杆诊断
├── PadTestActivity.kt     手柄输入测试（确认 KeyCode / 轴值）
├── MapperService.kt       无障碍服务：收按键 / 摇杆轴 + 注入触摸
├── StickEngine.kt         虚拟摇杆：摇杆量 → 长按 / 连滑手势
├── OverlayManager.kt      悬浮键位：显示 / 拖动 / 保存
├── MappingStore.kt        配置持久化（归一化坐标，换分辨率不丢）
└── PadKeys.kt             手柄键名表
```

配置文件存在 `SharedPreferences`，坐标用 0～1 归一化保存，所以横竖屏、换手机都能还原。
存档有版本号（`layoutVer`）：老的 v1.1 存档打开时会**自动补上**方向键和两个摇杆，
已经摆好的键位一个都不动。

## 注意

- 这是 **debug 签名**的包，可以正常安装，但不能上应用商店
- 各家 ROM（小米/华为/OPPO/vivo）对无障碍服务有额外限制，通常还需要在系统设置里单独允许「后台弹出界面」「自启动」「显示悬浮窗」，否则息屏或切后台后服务会被杀
- 摇杆轴数据只在 **Android 14+** 拿得到；低于 14 只能用十字键驱动移动摇杆
- 服务一旦开启就会「接管」手柄的摇杆 MotionEvent（系统不再把它们发给别的 App），
  所以这是全有或全无的：不用摇杆映射时，直接把无障碍服务关掉即可
